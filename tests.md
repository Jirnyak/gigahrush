# Tests

> Центральный документ стратегии проверок.
>
> Роль: что именно проверяется, какими командами, в каком состоянии находятся сьюты и как писать ассерты, чтобы они ловили регрессии, а не дрейф контента. Файл значится в таблице обязательного чтения `AGENTS.md`.

Актуально на 2026-08-24.

## Две непересекающиеся сьюты

Тесты физически разделены на два набора, и разделение автоматическое:

- `npm run test:unit` — `scripts/run-unit-tests.mjs`, конкурентность 3.
- `npm run test:generation` — `scripts/run-generation-tests.mjs`, конкурентность 2, выставляет `GIGAHRUSH_GENERATION_MATRIX=1`.

Правило отбора одно (`isGenerationCoupledTest`): файл уходит в генерационный набор, если его имя матчит `^items_\d+_` **или** исходник содержит `"../src/gen/"`. Всё остальное — юнит-набор. Исключения перечислены в `unitGenerationExceptions`.

Практическое следствие: любой тест, импортирующий что-либо из `src/gen/`, автоматически уходит в генерационный набор — и до 2026-08-15 это означало «исчезает из обязательного гейта». Так полоса и накопила поломки незаметно. Теперь матрица в `check`, но в `check:readonly` её нет, так что следствие живо для быстрой петли. Тесту, которому нужен контент, а не генерация, положен `import '../src/content'`.

## Что запускают гейты

| Команда | Состав | Когда |
| --- | --- | --- |
| `npm run typecheck` | строгий TS без артефактов | всегда дёшево |
| `npm run check:readonly` | typecheck + test:unit + content:audit + check:invariants | быстрая петля агента; матрицы генерации в ней НЕТ |
| `npm run check` | то же + **test:generation** + `build` (пишет `dist/`) | системные правки, генерация, save/load, AI, UI; примерно +13 минут |
| `npm run check:shaders` | компиляция и линковка ВСЕХ программ WebGL из `src/render/` в headless Chrome | после ЛЮБОЙ правки GLSL; ~6 с, ничего не пишет |
| `npm run check:browser` / `check:full` | + `check:shaders` + headless-браузер | render/UI/mobile/canvas/input; **зелёный с 2026-08-24** |
| `npm run smoke` | играбельность в браузере, нужен готовый `dist/` | после крупных правок мира; **зелёный с 2026-08-24** |
| `npm run test:generation` | матрица генерации (294 файла), ставит `GIGAHRUSH_GENERATION_MATRIX=1` | входит в `npm run check` с 2026-08-15 |

**Ошибка в GLSL до 2026-08-29 не была видна НИ ОДНОМУ гейту, и это худший вид слепоты: она даёт молча выключенную функцию при полностью зелёных проверках.** Шейдеры лежат в шаблонных строках, внутрь которых `typecheck` не смотрит; `createOptional*Pass` глотает исключение в `console.warn`; `smoke` считает провалом только `console.error` и потому остаётся зелёным на сломанном проходе. Закрыто командой `npm run check:shaders` — она поднимает настоящий контекст WebGL2 и линкует девять программ, включая три «глотателя» дважды: по имени напрямую и в живой сборке `initWebGL`.

Прибор проверяет сам себя ОБЕИМИ сторонами, прежде чем ему верить: заведомо битый шейдер обязан быть отвергнут, годный — принят. Провал любой стороны даёт код 2 и отказ подтверждать шейдеры, потому что вечнозелёная проверка (сломанный Chrome, потерянные флаги ANGLE) хуже отсутствия проверки. Красноту можно предъявить в любой момент: `npm run check:shaders -- --prove` портит один настоящий шейдер В ПАМЯТИ, не трогая файлы, и требует от отчёта покраснеть.

Ловушка при правке самих шейдеров: обратная кавычка в комментарии GLSL рвёт шаблонную строку, и это как раз ошибка, которую `typecheck` увидит, — а вот `float x = ;` он не увидит никогда.

`tsconfig.json` не включает `tests/`, поэтому `npm run typecheck` НЕ проверяет типы в тестах. Строку в тесте можно передать туда, где ожидается число, и узнать об этом только в рантайме. Именно так в кодовой базе жили тесты, писавшие `undefined` в слот и сравнивавшие `true` со строкой.

## Состояние на 2026-08-24

- **`npm run smoke` и `npm run check:browser` — ЗЕЛЁНЫЕ**, три прогона подряд EXIT=0.
  Многолетний «структурно красный» смоук закрыт. Беда была настоящей, но не в игре, а в
  приборе, и причин у неё три. (1) **Титры стоят ПОЗАДИ полной генерации случайного

  где HUD не рисуется и игрок не двигается, — оба падения «HUD пуст» объяснялись этим, и
  игра при этом была исправна. (3) Во время сцены безголовый прогон идёт **около 1.7 кадра
  в секунду**, а нажатие клавиши живёт 90 мс, поэтому одиночный тап укладывался МЕЖДУ
  кадрами и терялся, ни разу не прочитанным. Прибор теперь ждёт готовности вместо слепой
  паузы, жмёт до результата и снимает сцену после каждого перехода.

Два новых механических инварианта в `npm run check:invariants`:

- **`@ts-ignore` в `src/` запрещён (порог 0).** Под двадцатью шестью такими
  строками пряталось 53 ошибки типов; `@ts-expect-error` разрешён — он называет
  код ошибки и сам падает, когда ошибка уходит.
- **Мёртвая шкала этажей ловится в формах `case 100:` и `[180]:`.** Проверка
  умела только `z: N` и `z === N`, поэтому годами не видела `switch (z)` в
  `floorDanger` и ключи `floorWeights`. У `case` предмет разбора стоит строкой
  выше, поэтому он ЗАПОМИНАЕТСЯ — иначе либо слепота, либо ложные срабатывания
  на чужих `case 100:`. Проверено обратным контролем на копии дерева: возврат
  обоих мест даёт ровно 7 срабатываний.

### Приборы: как читать числа `arena-bench`

Стенд — не тест, и два его числа врут, если читать их в лоб.

- **«Застряло» и «насмерть» считаются В ЗНАМЕНАТЕЛЕ ЖИВОГО МАРШРУТА**
  (`stuckWindows / tryingWindows`, окно засчитывается только при `routed && !arrived`).
  Правка, дающая акторам маршрут там, где его раньше не было, ДОБАВЛЯЕТ тяжёлых окон в
  знаменатель и читается как регресс. Именно так «монстры залипают насмерть чаще» дважды
  докладывалось необъяснённым регрессом и оказалось ложной тревогой. Сверять безусловным
  прибором (`tmp/monster-stuck.ts`) и смотреть на долю без маршрута рядом.
- **Разброс между прогонами ОДНОГО кода — до ±1.7 п.п.** Одиночный прогон не отличает
  правку от шума: сравнивать медианы двух-трёх прогонов, лучше на 3600 тиках.
- **Неподвижные по замыслу виды завышают агрегат застревания примерно на 2.4 п.п.**
  Споровый ковёр никуда не идёт вовсе (он растёт по кровяному следу), но `speed` в его
  дефе ненулевая, поэтому фильтр прибора (`e.speed <= 0`) его пропускает и он даёт 100%
  окон без движения.

### GC-зависимые тесты

`world-live-count.test.ts` меряет, что собралось сборщиком мусора, поэтому ему нужен принудительный
GC. Флаг `--expose-gc` ему НЕ передаётся: файл импортирует `../src/gen/`, значит по правилу
маршрутизации уезжает в набор generation, а раннеры аргументы ноды не пробрасывают. Тест включает GC
сам, через `v8.setFlagsFromString('--expose_gc')` + `vm.runInNewContext('gc')`. Если будешь писать
такой же — не правь раннер, повтори приём. И помни, что `FinalizationRegistry` срабатывает ПОСЛЕ
сборки: число живых миров — верхняя оценка, ассертить по нему можно только после форсированного GC.

## Как писать ассерты: инварианты, а не микросостояние

Генератор этажа — детерминированная функция сида, и вся его работа — одна длинная цепочка потреблений ГПСЧ. Ассерт вида `rooms === 232` или `npcTarget === 1070` пиннит **точку траектории**: добавили один предмет в лут-таблицу → один лишний вызов `rng()` → вся последующая последовательность сдвинулась → тест красный, хотя игра не изменилась. Это как проверять газ в баллоне по координате конкретной молекулы.

Проверять надо макровеличины, выражающие дизайн-контракт:

- **границы масштаба**: «этаж маршрутного масштаба» = `rooms >= 320`, а не `=== 327`;
- **законы сохранения**: население ≤ кэпа акторов; каждая дверь одновременно в `world.doors` и в `room.doors`; из спавна достижимо всё проходимое;
- **непустота и наличие**: у торговца есть предмет; зона фракции существует; штаб имеет гермодверь;
- **монотонности**: глубже — опаснее; расширение не уменьшает связный объём;
- **цель профиля с допуском**: `npcs` в пределах ±10% от `npcTarget`, а не равно конкретному числу.

Ослабление ради зелёного цвета — не инвариант. У каждой границы должен быть смысл, и его стоит записать комментарием рядом. Если фактическое значение **качественно** неверно (ноль населения при живом авторском профиле, недостижимая комната, отсутствие обязательной сущности) — это находка, а не повод двигать порог.

Владелец утвердил эту линию явно: точные счётчики блокировали рост контента и прятали настоящие регрессии.

## Ловушки, которые уже стоили дней

- **Тесты не тайпчекаются.** Опечатка в имени константы даёт `undefined`, а не ошибку сборки. Так исчезли колонны: тест писал в слот код `undefined` → 0.
- **Ассерт без условия.** `assert.equal(true, "сообщение")` сравнивает `true` со строкой и красен всегда — так выглядит ассерт, у которого при автозамене выпало само условие. Искать: `grep -rn 'assert.equal($' tests/`.
- **Тип как значение в шаблоне.** `${number[floor]}` — след механической замены `FloorLevel` на `number`; падает в рантайме при формировании сообщения.
- **Старые координаты этажей.** Числа 60/100/140/180/200 и «представители» 2/-6/-14/-40 в данных и ассертах — почти всегда непромигрированное место. Канон: министерство 30, квартиры 14, жилой 0, коллекторы −26, ад −36, пустота −50.
- **Сюжетный пул id зарезервирован.** Обычные сущности обязаны получать id ВЫШЕ `getPlotNpcCount()` (сейчас 473 — длина `src/data/npc_plot_ids.ts`). Дизайн-этажи начинают с 10000; жилой начинал с единицы, и первые сотни предметов, монстров и столов выдавали себя за сюжетных NPC — проверки «этот человек уже есть» ложно срабатывали, а классификаторы A-Life (`alifeId >= 1 && <= getPlotNpcCount()`) видели сюжетных там, где их нет. Правило для новых генераторов: `nextId.v = getPlotNpcCount() + 1000`.
- **Слоты сюжетных личностей заморожены (было: позиционные id).** Числовой `plotNpcId` больше не индекс регистрации: он берётся из списка `src/data/npc_plot_ids.ts` и не зависит от того, какие модули импортированы. Новый NPC дописывается В КОНЕЦ списка, иначе поедут чужие слоты — сейв хранит именно числа. Замок: `tests/content-registration-order.test.ts`. Передавать `plotNpcId` числом снаружи всё равно не надо: связывание резерва A-Life идёт строковым `npc:<пакет>` (`npcReservedIdentityId`), и `reservedPlotSlot` специально предпочитает строку.
- **Контент надо попросить.** Реестр контента (пакеты NPC, сайд-квесты, зоны жилого) наполняется побочным эффектом импорта генераторов этажей. Раньше он приезжал транзитивно через `systems/samosbor`; ребро срезано. Тесту, которому нужен полный реестр или перестройка этажа самосбором, нужен явный `import '../src/content'`. Без него самосбор падает с внятным текстом, а не молчит.
- **Дом пакета NPC сверяется генерацией, а не глазами, и в обе стороны.** `tests/npc-home-floor.test.ts` (генерационная сьюта, ~77 с) строит все дизайн-этажи и требует двух вещей: у каждой заспавненной сущности `placement.homeFloorKey` совпадает с этажом, где она появилась, И каждый пакет, объявивший этаж, на нём присутствует. Первая половина ловит молчаливый дефолт `design:living` (регистрация без этажа не падает и не остаётся пустой, а это ключ бакета A-Life). Вторая половина ловит забытую строчку спавна — до единой доставки так пропали Олевия Кибер с квестом и семеро авторских жильцов. В ассерте список имён, а не число: контенту расти можно.
- **Шаг сюжета без дающего.** `tests/plot-giverless-steps.test.ts` (юнит-набор): шаг без `giverId` выдаётся сам, как только закрыт предыдущий, второй раз не выдаётся, до закрытия предыдущего не появляется и закрывается делом, а не разговором. Тест ищет первый шаг без дающего сам, а не помнит его номер: цепочка вправе расти.
- **Цена в тесте может держаться на случайном импорте.** `tests/systems-economy.test.ts` ждал цену с караванным тарифом, но сам караванов не импортировал: провайдер тарифа регистрируется на верхнем уровне `systems/caravans`, а модуль приезжал транзитивно через `economy → containers → factions → caravans`. Разрез ребра `containers → factions` убрал эту дорогу, и цена молча стала 12 вместо 13 — тест поймал не регрессию экономики, а свою необъявленную зависимость. Теперь она объявлена строкой `import '../src/systems/caravans'`. Правило то же, что и с реестром контента: нужен побочный эффект — попроси его явно; падение вида «число сдвинулось на единицу» после правки графа импортов ищи среди `register*`-провайдеров, а не в формуле.
- **Прямой импорт из слоя генерации выкидывает тест из гейта.** `scripts/run-unit-tests.mjs` уводит файл в набор `generation` по подстроке `../src/gen/` в его собственном исходнике, а этот набор не входит ни в один гейт. Так семь зелёных тестов `demos.test.ts` не проверялись ничем: файл тянул один модуль коллекторов ради Гордона. Нужен контент — бери `../src/content`.
- **Сырой генератор мимо заселения.** `generateKvartiry()` и подобные не проходят централизованное заселение из `generateDesignFloor`; тест, зовущий их напрямую, увидит десятки актёров вместо тысяч.
- **Подстрочный детектор контента.** Фильтр вида `room.name.includes('служеб')` считает не содержимое, а совпадения в именах: на базаре он видел 3 задворки из 14, потому что остальные названы «Северный склад краденых тюков» и «Задняя мастерская пломб». Считать надо по авторскому набору (экспортированный спек), тогда проверка ловит и то, ради чего писалась, — комнату, которая не построилась.
- **Строгая проходимость дверей ≠ запечатанность.** Обход, пускающий только `OPEN`/`HERMETIC_OPEN`, объявит отрезанной каждую комнату за закрытой дверью (на рынке — 91 из 321). Замок — это игровое препятствие; для проверки «нет отрезанного содержимого» дверь проходима в любом состоянии.
- **Дыра гейта: запрет `Math.random` не видит псевдонима (найдено 2026-08-20).** Проверка 2 в `scripts/check-invariants.mjs` — построчный regex `\bMath\.random\s*\(` по `src/**` мимо `core/rand.ts`, с базой `MATH_RANDOM_BASELINE = 2` (сетевые идентификаторы). Строка `import { mathRng as rng } from '../core/rand'` этому regex не видна вовсе: дальше по файлу стоит обычный на вид `rng()`, гейт зелёный, а случайность идёт через `Math.random()`. Так под зелёным гейтом жил целый класс — девять настолок и игровой автомат, то есть код, чья ставка уходит в `player.money`: недетерминированная партия открывает сейв-скам и расхождение хоста с пиром в онлайне. Переведено на общий `rng()`, замок — `tests/games-deterministic.test.ts` (один сид → та же партия; разные сиды → расходятся; сами модули не содержат ни `mathRng`, ни `mathIrand`, ни `Math.random`). **Дыра в гейте остаётся открытой**: инвариант по-прежнему ловит только сырой вызов, поэтому новый `mathRng` в логике, попадающей в деньги, сейв, AI или тесты, ищется чтением, а не гейтом. Диагностический прогон: `rg -n "mathRng|mathIrand" src/`; сейчас это ~59 мест в `src/systems/`, легитимные из них — визуал, звук и несимуляционные роллы UI (`camera.ts`, `blood_fx.ts`, `ai/barks.ts`, `data/tips.ts`, `entities/sculpture.ts` и подобные; `data/critters.ts` из этого списка выбыл 2026-08-22 — фоновая живность стала функцией от полей мира и не роллит вообще).
- **Красный тест может охранять замысел.** Убирая глушитель населения по поясу |z| ≥ 44, мы получили новое падение `procedural-floors.test.ts:5420` (`roof.npcTarget === 0`). Это был не стухший счётчик, а записанный контракт «крыша — терминус без NPC»; правильный ход — перенести замысел в профиль этажа, а не ослабить ассерт. Прежде чем двигать порог, прочитай комментарий рядом с ним.
