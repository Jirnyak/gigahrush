# GIGAH|RUSH / ГИГАХРУЩ

> Центральный документ проекта (Factual Implementation Map).
>
> Роль: единая факт-карта игры, текущих shipped systems, параметров сборки и рабочих команд. Все остальные root-документы являются ключевыми системными томами вокруг этого манифеста: они уточняют AI, A-Life, этажи, самосбор, сохранения, бой, экономику, баланс, предметы, крафт, монстров, квесты, оптимизацию, стиль, тексты, online/mobile контуры. Манифест не должен обещать незавершенное; он фиксирует только то, что реально есть или является проверенным контрактом проекта. `README.md` — публичная страница проекта, она соавторская и источником истины НЕ является.

**GIGAH|RUSH / ГИГАХРУЩ** — zero-runtime-dependency TypeScript/Vite browser game: procedural survival-horror life-sim / ARPG shooter inside a 1024x1024 toroidal concrete megastructure.

Процедурные текстуры, процедурные спрайты, процедурный звук, WebGL рейкастинг, canvas HUD, плоские массивы сущностей, typed-array хранилище мира. Без фреймворков, без сторонних ассет-пайплайнов, сборка в один клик.

Наш долгосрочный фокус — довести симуляцию до состояния «генератора историй» (как Dwarf Fortress или Space Station 13), где A-Life, процедурная генерация и Самосбор постоянно создают непредсказуемые эмерджентные ситуации, о которых игроки будут рассказывать байки.

**GIGAHRUSH MEGA-UPDATE Features:**
- New Liquidator Base (База Ликвидаторов)
- New Armor items and Damage type system (5 типов урона и система брони)
- New immersive Tutorial sequence (Обучающие квартиры)
- Expanded Horror Floors and cinematic encounters (Хоррор-этажи и синематика)

Порядок хранения не является физикой мира. Индексы сущностей, комнат или фабрик в массивах `world.rooms`, `entities` не должны влиять на игровые решения. Bounded optimization must preserve isotropy through actor-local cursors, deterministic rotated windows, spatial queries, scoring before truncation or explicit authored priority. A stable first-prefix scan such as "first 96 rooms" is hardcoding by storage accident and is forbidden for gameplay-visible decisions.

Единая сущность «Игрок == NPC»: Игрок — это обычный NPC, которым управляет пользователь. У него одинаковые механики боя, социальная математика (`karma`, `playerRelation`, ранг), характеристики (`str`, `agi`, `int`) и тип сущности. Разделение происходит только в источнике ввода, камере и UI HUD. Система одержимости PSI меняет ссылку `player` на другого NPC или монстра и возвращает обратно. Нативная сущность игрока помечается `persistentNpcId: 'player'`.

Прямое следствие, уже отгруженное в коде: **мир не спрашивает, где стоит игрок.** Монстр не переключается на игрока отдельной проверкой мимо луча и кадансов; дальность обнаружения — свойство наблюдателя, а не отношения к игроку; сектор фракционного события выбирается по территории и населению, а не по клетке игрока; судьба каравана под самосбором читается из фактов мира под самим караваном. Детали — «Выбор цели и дальность обнаружения» ниже.

Этот манифест — фактологическая карта реализации. Приоритеты дизайна следующей итерации находятся в [desdoc.md](desdoc.md). Инженерное владение и правила модулей описаны в [architecture.md](architecture.md). Инструкции агентского поведения зафиксированы в [AGENTS.md](AGENTS.md).

### Рабочие команды (npm-скрипты)

Для проверки и сборки используются только существующие скрипты из `package.json`:

```bash
npm run typecheck       # Строгая проверка типов TypeScript (без создания диста)
npm run test:unit       # Модульные тесты через tsx --test
npm run test:generation # Расширенная матрица генерации этажей
npm run content:audit   # Статический аудит контента и реестра
npm run check:readonly  # Набор быстрых проверок: typecheck + test:unit + content:audit
npm run build           # Продакшн-сборка single-file приложения в dist/
npm run smoke           # Headless-проверка кликабельности и спавна (требует Chrome)
npm run check           # Стандартный CI-гейт (выполняет build)
npm run check:browser   # Расширенный гейт проверки рендера и UI
npm run check:full      # Полная проверка (включая браузерные тесты)
npm run check:release   # Гейт подготовки релизного артефакта (dist/ и itch/)
```

Назначение команд:
- `npm run typecheck`: строгий префлайт TypeScript; не создает артефактов в репозитории.
- `npm run test:unit`: модульные тесты Node.js через `tsx --test`.
- `npm run test:generation`: расширенная матрица генерации этажей.
- `npm run content:audit`: статический аудит исходников и контента.
- `npm run check:readonly`: typecheck, unit-тесты, content audit; самый безопасный гейт.
- `npm run build`: продакшн-сборка single-file приложения для браузера; пишет в `dist/`.
- `npm run smoke`: headless-проверка играбельности в браузере; требует существующего `dist/` и Chrome.
- `npm run check`: дефолтный CI-гейт; пишет в `dist/`.
- `npm run check:browser` / `npm run check:full`: запуск при изменениях рендера, UI, мобильного ввода и холста.
- `npm run check:release`: гейт релизного артефакта; пишет в `dist/` и `itch/`.

## 2. Архитектура, слои и правила владения файлами (Architecture & File Ownership)

Проект строго соблюдает **5-слойную архитектурную контрактную модель**:

- `core/` — примитивные типы, перечисления, константы, тороидальный `World` и общие формы состояния. Изменения здесь — интеграционная работа.
- `data/` — реестры определений (предметы, оружие, сюжет, экономика, пропуска, терминалы, варианты). Без мутаций мира, фреймовой логики и DOM.
- `gen/` — генераторы комнат, коридоров, POI, начальное размещение, контент этажей.
- `systems/` — общая рантайм-логика (AI, квесты, A-Life, Самосбор, фракции, экономика, сохранения, взаимодействия). Системы потребляют определения и публикуют факты.
- `render/` — WebGL рейкастер, процедурные спрайты/текстуры, canvas HUD, карты и оверлеи. Только чтение состояния; не принимает решений о геймплее.

`entities/` содержит пакеты определений сущностей и генераторы спрайтов; это не иерархия классов. `main.ts` владеет порядком игрового цикла и высокоуровневой обвязкой.

### Запрет на хардкод-таймеры обрыва логики (Anti-Pattern: Logic-aborting Timers)

**Строго запрещено** использовать жестко зашитые таймеры (например, `ai.timer = 1.5 + rng() * 2.5`) для принудительного прерывания нормальной физической или навигационной логики (например, заставляя NPC бросить незаконченный маршрут на полпути и выбрать новый).
- Сущность должна завершить начатое действие (например, дойти до конца `ai.path`), либо столкнуться с реальным физическим препятствием (которое корректно обработает система коллизий через `ai.stuck`), либо прерваться из-за легитимного внешнего раздражителя (урон, враг).
- Любые отвлечения от текущего пути должны происходить **исключительно из игрового контекста** (увидел врага, получил урон, услышал шум), а не по истечению случайного таймера.
- Говнотаймеры, которые слепо обнуляют путь (`ai.path = []`) или заставляют сущность передумывать посреди дороги, создают дерганое, психотичное поведение и ломают читаемость намерений ИИ. Дайте сущности дойти до цели.

### Границы владения файлами (File Ownership & Zone Safety)

- **Зелёная зона (Безопасно для аддитивных изменений)**:
  - Новые `src/gen/<floor>/<module>.ts`
  - Новые `src/gen/design_floors/<id>.ts` с регистрацией в манифесте
  - Новые `src/gen/procedural_anomalies/<module>.ts` с хуком в данные/системы
  - Новые `src/data/<domain>_<module>.ts` или локальные файлы определений
  - Новые `src/entities/<monster>.ts`
  - Новые тесты под `tests/`
- **Жёлтая зона (Точечные аккуратные правки)**:
  - `content_manifest.ts` в папках этажей
  - `src/gen/living/side_quests.ts`
  - `src/gen/floor_manifest.ts`
  - `src/gen/design_floors/manifest.ts`
  - `src/data/items.ts`, `src/data/weapons.ts`, `src/data/psi.ts`, `src/data/plot.ts`
  - `src/entities/monster.ts`
  - `src/render/sprite_index.ts`, `src/render/sprites.ts`, `src/render/textures.ts`
  - `src/systems/debug.ts`, `src/systems/debug_cheats.ts`
- **Красная зона (Только для интеграторов)**:
  - `src/core/types.ts`
  - `src/core/world.ts`
  - `src/main.ts`
  - `src/gen/shared.ts`
  - Глобальные переработки AI/патрайдинга/боя
  - Общие переработки квестов, инвентаря, Самосбора, сохранений или рендера
  - `src/render/webgl.ts` (за исключением добавления универсального канала рендера)

### Генерация случайных чисел (Randomness Contract)

Вся игровая случайность проходит через детерминированный xorshift32 генератор в `src/core/rand.ts`. **Использование `Math.random()` в игровом коде строго запрещено.**

Доступный API:
- `rng()` — глобальный генератор, возвращает `[0, 1)`. Единственный источник случайности для геймплея, генерации, AI, лута, спавна, FX и роллов UI.
- `irand(lo, hi)` — целое число в `[lo, hi]` включительно.
- `seedGlobalRng(seed)` — повторное засеивание (при старте рана и переходе этажа).
- `seededRandom(seed)` / `SeedRng` / `xorshift32(seed)` — локальные детерминированные последовательности для воспроизводимого процедурного контента.
- `pickFrom(arr)`, `shuffleWith(arr, rand)`, `irandFrom(rand, lo, hi)` — утилитарные обертки.

**Санкционированное исключение — `mathRng()` / `mathIrand()`.** В `rand.ts` есть
пара обёрток поверх `Math.random()`, намеренно предназначенных **только** для
чисто-косметической случайности: визуал (вспышки урона, кровь, партиклы),
аудио/музыка и не влияющие на симуляцию роллы UI. Их разрешено использовать там,
где недетерминизм **не может** рассинхронизировать геймплей, AI, тесты или
онлайн. Категорически **запрещено** звать `mathRng`/`mathIrand` (как и сырой
`Math.random()`) в геометрии, генерации, AI, луте, спавне и любой логике,
попадающей в сейв или детерминированные тесты — там только `rng()` /
`seededRandom` / `xorshift32`. Единственное дополнительное исключение для сырого
`Math.random()` — крипто/сетевая идентичность (`net_sphere.ts`,
`online_client.ts`), где детерминизм создал бы риск коллизий.

**Деньги — не косметика.** Все девять настолок, бросок костей, тасовки колод,
расстановка флота морского боя, выбор залпа, цвет мела и выигрыш игрового
автомата переведены с `mathRng` на общий `rng()`: ставка уходит в `player.money`,
поэтому недетерминированная партия открывала сейв-скам (переиграть до выигрыша)
и расхождение хоста с пиром в онлайне. Замок — `tests/games-deterministic.test.ts`,
проверяет обе стороны: один сид даёт одну и ту же партию, разные сиды расходятся,
и ни один из этих модулей не тянет `mathRng`/`mathIrand`/`Math.random`.
**Ловушка гейта**: `npm run check:invariants` ищет только сырой `Math.random(` и
псевдоним `import { mathRng as rng }` не видит — подробности в `tests.md`.

## 3. Вертикальный мир и система этажей (Vertical World & Floor System)

Мир ГИГАХРУЩА — это 1024x1024 тороидальная бетонная мегаструктура. Вертикальный мир состоит из **101 этажа** по первичному маршруту `FloorRun` от `z = -50` до `z = +50`.

### Единая архитектура генерации этажей и Политика смены уровня

- **Четные этажи (`Z % 2 === 0`)**: Автономные авторские дизайн-модули (`design_floors` / `design:*`). Устаревшая концепция отдельной генерации «story floors» полностью консолидирована в дизайн-модули: каждый авторский этаж строится как самостоятельный пакет со своей геометрией, экологами, фракциями и правилами.
- **Нечетные этажи (`Z % 2 !== 0`)**: Процедурно собираемые промежуточные этажи (`procedural:*`), случайным образом комбинирующие куски геометрии других блоков и аномальные эффекты.
- **Политика честной генерации при переходе**: При переходе на любой этаж мир детерминированно генерируется заново по сиду рана и координате уровня (`(runSeed, z)` → идентичная геометрия при ревизите через лифт). Уходящий этаж не удерживается: его NPC сворачиваются в A-Life, а `World` отбрасывается. Потолок — `MAX_LIVE_WORLDS` = 2 живых `World`: играемый этаж плюс второй только на время перехода и как кеш лифта на один этаж назад (`MAX_FLOOR_MEMORY_ENTRIES = 1`). Это не декларация, а измеряемое число: `liveWorldCount()` на `FinalizationRegistry` (`src/core/world.ts`), замок — `tests/world-live-count.test.ts`. Держится тем, что поэтажное состояние контентных модулей живёт в `createWorldContextStore()` (`src/world/world_contexts.ts`) — один мир, ключ по комнате — и сбрасывается единой точкой выгрузки `dropWorldContextsExcept()` в `finishLoadedFloorVisuals()`; модули с одиночным слотом подключаются к ней через `registerFloorScopedReset()`. До 2026-08-16 утверждение было ложным: девятнадцать модулей удерживали по этажу каждый, шесть переходов оставляли 477 МиБ `arrayBuffers` вместо 127 — это и был мобильный OOM. Сейв хранит только снапшот текущего активного этажа — и не полной геометрией, а компактной дельтой поверх заново сгенерированной по `(runSeed, z)` базы (XOR 12 мировых массивов + разреженные diff комнат и дверей; сущности, контейнеры и зоны — абсолютные), чтобы уложиться в ~5 МБ `localStorage`; дрейф базы между сохранением и загрузкой ловит хэш-страж `baseHash` и откатывает к честной регенерации этажа, а не к порче сетки. Правки игрока на активном этаже — выброшенный лут, вскрытые контейнеры, трупы, сломанные двери — переживают сохранение; плюс хранится компактная макропопуляция A-Life; хранение громоздкой полной геометрии всех этажей упразднено. См. [save.md](save.md).
- **Единый источник правды для NPC (Macro A-Life Pool)**: Состояние, характеристики, инвентарь и репутация всех NPC хранятся в едином макро-пуле A-Life (`AlifeState.npcs`, 100 000 записей). При генерации этажа NPC не создаются «с нуля», а воплощаются в физическую форму из текущих записей A-Life пула для этого этажа.
- **Принадлежность может переписать СОБЫТИЕ (с 2026-08-27)**: `setAlifeNpcFactionOverride` / `getAlifeNpcFactionOverride` (`systems/alife.ts`) держат разреженную карту «слот → фракция», которая накладывается в проходе материализации рядом с фильтрами мёртвых и переехавших и уезжает в сейв. Отдельный факт понадобился потому, что колонка фракций у сюжетного слота живёт лишь до следующей генерации его этажа: тело авторского NPC рождается из анкеты пакета заново, и без оверрайда перебежчик из такта `defect` возвращался бы своим при первом же возврате. Это общая механика, а не оснастка одной сцены. Замок — `tests/alife-faction-override.test.ts`.
- **Глубина этажа доходит до личности (с 2026-08-27)**: опасность записи A-Life берётся из авторского `DESIGN_FLOOR_ROUTES[].danger`, и от неё считаются уровень, достаток и состав фракций. Второй шкалы опасности в проекте нет. До этого `sanitizeFloor` держал окно старой шестиключевой шкалы (`>= 30 && <= 200`), отвергал всё ниже министерства и подменял координатой `100`, а `floorDanger` разбирал ту же мёртвую шкалу и возвращал `undefined`; колонка `columns.z` была `Uint8Array` и отрицательную высоту не вмещала. Измеримое следствие: средний уровень населения мясного низа и жилого этажа совпадал до последнего знака. Таблица `floorWeights` (`data/alife_generation.ts`) переведена на канон теми же ключами (100→0, 60→14, 140→−26, 180→−36), поэтому культисты снова весят на мясном низу столько, сколько написал автор. Замок — `tests/alife-floor-depth.test.ts`.
- **Часть населения можно ПЕРЕВЕЗТИ, а не доспавнить (с 2026-08-27)**: `migrateAlifePopulation(state, { id, faction, fromFloorKey, toFloorKey, count })` увозит существующие личности заданной стороны с этажа-донора на этаж-получатель — донор редеет ровно на приехавших, вместе с людьми переезжают и цели раздачи мест, факт публикуется событием `alife_migration`. Кто поедет, решается детерминированно от семени A-Life и ИМЕНИ события, одним проходом по бакету донора; именные личности не увозятся; верхняя граница одного события — минимальный пул этажа (`ALIFE_MIGRATION_BATCH_CAP`). Имя случившегося переселения лежит в сейве, поэтому вторая волна тех же людей невозможна, а пустой донор — законный ноль. Закон «никакого добора фонового населения» цел: новых людей не рождается. Замок — `tests/alife-population-migration.test.ts`.

### Маршрутные и Быстрые Лифты (Lift Contracts & Protection)

- **Защита всех лифтов маской `aptMask` от Самосбора**: Все клетки кабин лифтов (как маршрутных, так и быстрых 8x8) строго защищены глобальной маской `aptMask`. Волна Самосбора, аномальные взрывы и алгоритмы динамической перестройки геометрии никогда не могут уничтожить, замуровать или перестроить клетки лифтов.
- **Маршрутные лифты (16 вверх / 16 вниз, единая система шахт)**: этаж НЕ решает, где его лифты — это единственная механика, которой связаны соседние этажи, и она живёт вне модулей. Позиции даёт чистая функция `routeLiftShaftCells(runSeed, ребро)` (`src/data/route_lift_shafts.ts`) по ключу РЕБРА между этажами, поэтому лифты вниз этажа — те же клетки, что лифты вверх этажа под ним: зеркальность выходит из арифметики, а не из переноса якорей. Ставит их `stampRouteLiftShafts` (`src/world/route_lifts.ts`), и зовут её обе стороны — генерация и рантайм. Сетка 4×4 шагом 256, в каждой ячейке одна шахта, точка внутри ячейки гуляет по сиду пары этажей. Шахта не садится на защищённую клетку (`aptMask`), в дверной проём и в горловину коридора; подход к ней прорубается. Замер до системы: 12 дизайн-этажей из 51 несли разное число лифтов вверх и вниз (от 0/1 до 1/16), после — 16/16 на всех 51.
- **Сеть быстрых лифтов (Fast Elevators Network)**: На каждом этаже генерируется не изменяемая сетка из 16 кабин (4×4, шаг 256 клеток, смещение +128), помеченная `Cell.LIFT` + `Feature.MACHINE`. Это ДРУГАЯ система, чем маршрутные лифты: кабина везёт на любой уже открытый этаж, маршрутный лифт — только на соседний.
- **Разблокировка Фаст-Тревела (`unlockedZs`)**: При взаимодействии `E` с кабиной быстрого лифта текущий этаж `z` мгновенно заносится в список доступных этажей рана `FloorRunState.unlockedZs` для быстрого перемещения (стартовый этаж `z=0` разблокирован изначала).

### Переменная высота потолков и сквозная прозрачность (Ceiling Heights & See-Through)

Высота стен и потолков — рендерная метаданная `world.ceilHeight`, запекаемая в `src/world/ceiling_heights.ts` при загрузке/восстановлении этажа (тир `t` → высота `1 + t*0.5`, `getCeilingHeightForTier`). Она не влияет на 2D-коллизии и навигацию.

**Ярус выводится из формы пространства, а не назначается таблицей** (с 2026-08-16): `ярус = clamp(floor(log2(1 + свободный_радиус)) + сдвиг_роли, 0, 3)`. Четыре прохода: (0) distance transform по открытым клеткам с заворотом по тору, у комнаты — вписанный радиус, один на всю; (1) ярус по формуле, сдвиг роли ±1 (кладовая и санузел ниже, цех, штаб и зал выше); (2) один проход диффузии — соседи не расходятся больше чем на ярус; (3) стены поднимаются до самого высокого открытого соседа. Ступенька приходится на удвоение радиуса (1..2 → 1, 3..6 → 2, 7..14 → 3), потолок выведенного яруса — прежний парадный 3: выше начинается то, что запечённый свет уже не несёт. Авторский `room.ceilingTier` и глобальный `world.globalCeilingTier` ставятся как есть, формулой не выводятся и диффузией не размываются. Бэйк — 40–65 мс на этаж, только при смене этажа. Прежние пороги `LARGE_AREA`/`GRAND_AREA` и таблицы «тип комнаты → высота» у министерства и коллекторов удалены.

Единая универсальная система **сквозной прозрачности** (BLAME-стиль вертикальной пустоты) включается пер-этажным флагом `world.hasOpenSky` (сейчас Крыша `z=+50` и Наружний микрорайон `z=+48`) и решается пер-клеточно по тиру, поэтому миксуется на одном этаже:
- **Конечная стена** — стена берёт высоту интерьерного соседа; рейкастер (`webgl.ts`, ceiling-march `uHasOpenSky`) показывает над её верхом пустоту и небо. Снаружи домов — открытое небо над стенами, внутри — бетонный потолок.
- **Скайлайн-силуэт** — стена, граничащая только с небом (внешние башни, парапеты), получает детерминированный варьированный силуэт; над самым высоким — небо.
- **Клетки `DOOR`/`LIFT`/`ABYSS`** на открытых этажах тоже приводятся к конечной высоте (не уходят столбами вверх).
- **Небо объявляют только уличные комнаты, интерьер выводится формулой.** На Перекрёстках снят бланкетный проход `for (const room of world.rooms) room.ceilingTier = 198` (красил небом и интерьеры зданий — потолка внутри домов не было вовсе; стало 63% неба / 37% интерьеров на ярусах 1–3), у панельки Наружного микрорайона снят авторский `ceilingTier: 4` = 3.0 м (интерьеры легли на 1.5–2.0 м).
- Порог `SKY_TIER_THRESHOLD = 8` разделяет интерьерные тиры (выведенный ярус живёт в `0..7`) и открытое небо (Крыша 14, улица 240). Он же задаёт кэп санитайзера `validateFloorGeometry`: раньше там стояла жёсткая двойка, из-за которой процедурный этаж физически не мог иметь зал выше 2.0.

Высоту читают **два независимых рендерера** — рейкастер `webgl.ts` и инстансированные меш-колонны `src/render/mesh/scene_collect.ts` (`applyCeilingHeight`, клампится по `SKY_TIER_THRESHOLD`, чтобы колонны не растягивались до неба). Всё поведение gated по `hasOpenSky`: закрытые этажи (интерьеры, каньоны Перекрёстка `z=+8`) рендерятся байт-в-байт как раньше.

#### Свойство вида — флаг, а не поле ядра (2026-08-20)

Правило: вид объявляет своё свойство флагом в `aiFlags` и приносит спрайт в своём файле `src/entities/<вид>.ts`. Поле в `AIState` (`src/core/types.ts`) или собственная функция в общем `src/systems/ai/monster.ts` ради одного вида — запрещены: `AIState` носит каждая сущность мира. Состояние вида, если оно нужно, живёт в `WeakMap` рядом с видом (так работают Собранный, Слизевая женщина, Зелёная собака, Туманная акула и Кошмар — их поведение при чистке не изменилось).

**Снесено целиком** (виды, спрайты, записи экологии и слухи сохранены):

- ложный патруль Чёрного ликвидатора — стук в дверь, нейтральная фаза и разоблачение по запретной пробе; вместе с ними ушли `updateFalseLiquidatorPatrol`, `findFalseLiquidatorRevealTrigger` и флаг `falsePatrol`;
- фазовый проход дверей Ложного Духа (`updateLozhnyyDukhFalsePhase`) — телеграф «холодный сквозняк», окно срыва точным выстрелом или УФ. Его флаг `falsePhase` оказался дублем `noclip`, вид переведён на `noclip` без изменения поведения;
- второй темп Глубинной Тени (`updateGlubinnayaTenSecondBeat`, флаг `secondBeat`) — afterimage-якорь и отложенный боковой удар; вид остался без флагов вовсе;
- восемь мёртвых полей Собранного (`composite*`, `meatGrowth*`) и Олгоя (`meatScanOffset`) — сами повадки живы, состояние переехало в `WeakMap`.

Итог: из `AIState` вычищено **25 полей**, из `ai/monster.ts` — около 800 строк.

**Чёрный ликвидатор пересобран как образец нового формата.** Всё свойство вида — внешность, и она в его собственном файле:

- `generateSprite()` берёт запечённый арт настоящего ликвидатора через `getGeneratedArtSprite` (`liquidator_m_1/3/5/6`) и процедурно ставит меловой номер на маску. Замаскированный вид совпадает с настоящим ликвидатором на 99.9% пикселей — это и есть канон слуха `ecology_black_liquidator_masks`: «у чёрных номера на масках мелом, не краской». Если арт не запечён, остаётся полностью рисованный fallback `generateBlackLiquidatorSprite`.
- Режима два, различает существующее поле `monsterStage` (прецедент — головной слизень), новых полей ядра нет. Пока рядом больше одного постороннего — держит форму, и настоящие NPC-ликвидаторы его не трогают: флаг `looksLiquidator` даёт одну строку в `isHostile` (`src/systems/factions.ts`).
- Остался с жертвой один на один ИЛИ получил урон — сбрасывает маскировку (`monsterStage = 1`), меняет спрайт на чёрный силуэт и дальше ведёт себя как обычный враждебный монстр. «Меня били» читается из общей памяти угроз (`getRecentCombatThreat`), свидетели считаются раз в пару секунд вразнобой по id.

**Второй заход по классу, 2026-08-23: десять видов, шесть новых механик.** Владелец решил
менять замысел, а не выселять состояние. Каждая механика — одно правило, из которого
динамика растёт без исключений в общем коде:

- **Мухожук** (`systems/ai/mukhozhuk.ts`, флаг `larvaCarrier`) кусает раненого ниже
  половины HP и оставляет личинку. Вылечили выше 80% — не прижилась. Не вылечили за 48 с —
  носитель умирает и выпускает нового мухожука. Умер раньше от чего угодно — личинка
  выходит сразу: добить своего раненого значит ускорить проблему. Реестр личинок — короткий
  `Map` с потолком 24, тик рядом с `expireMonsterBaits` в `updateAI`.
- **Туманник** (`systems/ai/tumannik.ts`, флаг `strikeReveal`) виден только в миг удара:
  окно считается от его же отката атаки (55%, потолок 0.85 с), своего таймера нет. Вне
  удара проступает по запечённому свету — в темноте не виден вовсе, при полном свете
  наполовину прозрачен.
- **Безэхий** (флаг `silent`) не шумит и не слышит: обе стороны стоят в дверях
  `systems/noise.ts`. Цель — только та, что в прямой видимости вблизи; за угол ушёл —
  потерян насовсем.
- **Дикий мертвяк** (`systems/ai/dikiy_mertvyak.ts`, флаг `noBrakes`) берёт курс ОДИН раз
  и больше его не правит: едет туда, где цель была. Удар о бетон — 1.6 с оглушения через
  общий `staggerTimer`.
- **Слизневик** (`systems/slimevik.ts`) глотает всё брошенное на пол (до 4 предметов) и
  носит в себе; раненый убегает с добычей. Возврат — общей дверью `dropMonsterLoot`.
  Брошенная вещь работает и как приманка, которой его уводят.
- **Споровый ковёр** (`systems/ai/spore_carpet.ts`) не ходит и не нападает: раз в 6 с
  щупает соседние клетки и прорастает по кровяному следу, гася его. Потолок 4 отростка.
- **Олгой** идёт на место смерти по полю крови (`findBloodTrailCell`), а не на
  труп-сущность: тело может исчезнуть, запах держится сам.
- **Лишенный, водяной кошмар, хоровая матка, протокольник** — механика прежняя, состояние
  выселено в `WeakMap` через `speciesState()`.

Итог второго захода: **`AIState` 136 полей → 80**, из `render/webgl.ts` вырезан весь
спецкод туманника (вместо него общее поле `Entity.spriteAlpha` и один uniform), тексты
всех десяти видов переписаны под новую механику.

**Запечённый арт как вход процедурного спрайта.** PNG-арты художника попадают в игру: `scripts/generate-art-sprites.mjs` читает манифест `src/data/art_sprite_manifest.ts`, распаковывает PNG и запекает их в `src/render/generated_art_sprites.ts` (генерируемый файл, руками не правится); `getGeneratedArtSprite(id)` отдаёт готовый `Uint32Array` 128×128. Пайплайн процедурных спрайтов такой размер принимает — `createSpriteTexture` в `src/render/webgl.ts` берёт сторону как `Math.sqrt(spr.length)` и пересэмплирует в `SPRITE_TEX_SIZE`, поэтому генератор вида вправе вернуть 128×128 вместо обычных 64×64. Отдельного npm-скрипта у запекания нет, оно запускается вручную; потребители сейчас — `src/entities/npc_visuals.ts` и `src/entities/black_liquidator.ts`.

### Выбор цели и дальность обнаружения (`systems/ai/combat.ts`, `systems/ai/monster.ts`)

- **Дальность обнаружения — свойство НАБЛЮДАТЕЛЯ.** В `tryFactionCombat` она равна `max(смелый ? NPC_CHASE_RANGE : NPC_COMBAT_RANGE, дальность его оружия)`; урон извне (`getRecentCombatThreat`) даёт форсированную цель с дальностью `max(NPC_CHASE_RANGE, maxRange)`. Отношение к игроку в расчёт не входит, и параметра `player` у функции больше нет. Раньше дальность бралась из враждебности к игроку: в одном бою враждебная сторона видела на `NPC_CHASE_RANGE`, дружественная — на `NPC_COMBAT_RANGE`, и мир вёл себя по-разному в зависимости от того, есть ли на этаже игрок.
- **Порог «боец/небоец» снят.** По сторонам смотрят все: небоец в этой ветке не дерётся, а замечает угрозу и убегает. Смелость и оружие решают только дальность.
- **Блока «Prefer player» у монстров нет.** Монстр больше не перемеряет расстояние до игрока после честного выбора цели и не переключается на него мимо проверки луча, кадансов сканирования и враждебности. Цель выбирают общие функции, игрок проходит через них наравне со всеми. Особые повадки сохранились в своих ветках выбора цели и написаны про любого носителя признака: `findDocumentHunterTarget` (печатоед), `findMeatWormTarget` (олгой — мясо и кровь, без множителя «игрок вкуснее»), `findChernoSlizTarget`, `findPomoynyRoyTarget` (радиус запаха считается от любого носителя приманки), `findBezekhiyEchoTarget` (порог сторожится для любого прохожего). Ржавник просыпается на того, кто в него попал (память угроз), Червие выписывает подменённый приказ на ближайшего человека, Чёрный ликвидатор считает свидетелями любых посторонних вокруг себя, а не игрока.
- **Единая дверь урона (с 2026-08-23).** Здоровье актору снимает `damageActor` (`systems/combat_stimulus.ts`) и только он: считает тип и броню, толкает, СООБЩАЕТ ЖЕРТВЕ, кто ударил, начисляет штраф отношениям и доводит смерть до общей обработки. До двери каждый бьющий делал эти пять шагов сам, и половина забывала — `notifyActorDamaged` знали три файла из всех, снимавших здоровье: весь пси-арсенал игрока бил без автора, гнилушка и слизевик в тишине, а одиннадцать спецударов монстров убивали вообще без обработки смерти, без крови и без лута. Молчание было поведением по умолчанию, потому что единственный общий помощник `applyDamage` только считал число. **Броня теперь работает для всех**, а не привилегией игрока: её конвейер читали четыре места, все в точке сборки, и удары NPC и монстров шли мимо. Обработка смерти приходит инъекцией (`setActorDeathHandler`), потому что принадлежит точке сборки; смерть игрока дверь не объявляет — у неё своя дорога. Отсутствие автора — полноправный случай: голод, обвал, среда и поезд бьют без виновника. Замок — инвариант `урон мимо двери` в `npm run check:invariants` (храповик, только вниз: 24 → 13, остаток — уже сообщающие пути) и `tests/unanswered-hits.test.ts`.
- **Ядро актора решает, бой исполняет (с 2026-08-23).** `systems/actor/` (senses → needs →
  drives → brain) идёт в `updateAI` перед боевым слоем и распорядком. Драйвы — строки
  данных с четырьмя ярусами исполнения: шаг по склону поля, дальняя цель маршрутом,
  комната по назначению, противник. Драка (`fight`) объявляет цель и уступает ход боевому
  слою; если побеждает не она, ядро снимает цель и боевую память — так работает разрыв
  контакта. Драка требует ЛИНИИ ВЗГЛЯДА, страх и укрытие — нет. Захват территории —
  такой же драйв (`capture`), отдельного фракционного отправителя на фронт больше нет.
- **Распорядок — тоже драйвы (с 2026-08-24).** Работа, разговор, обход, склад и роуминг
  переехали в ядро строками данных на ярусе комнаты. Ядро получило третий род входа —
  время суток (`systems/actor/clock.ts`, снимок общий на кадр); час смены входит
  множителем контекста, поэтому ночью работа честно ноль. Игровая фактура смены —
  складской цикл (покупка за деньги, кража со свидетелями, кормление вставших цехов,
  разнос по «природному адресу», защита квестовых вещей), уборка поверхностей и рейсы
  кладовщика — вынесена в `systems/npc_work.ts` и зовётся хуком прибытия. Патруль больше
  не ходит вне комнат: он адресуется аффордансом `patrol`. Замер жилого этажа: NPC
  застряло 16.3% → 9.0%, без маршрута 12% → 6.0%, `p50 updateAI` 1.19 → 1.08 мс, доля
  населения под ядром 24% → 48%.
- **У дела есть голос (с 2026-08-24).** Речь — побочный эффект занятия: у драйва есть
  строка `voice` (сигнал корпуса реплик, запасная строка и отдельная реплика прихода), и
  звучит она на смене драйва и на прибытии. Занятие уходит в общее марковское ядро тегом
  `activity.<драйв>` вместе с меткой обычного жителя и нуждами — прежде обстановка барка
  строилась ТОЛЬКО из авторского пакета, которого нет ни у одного обычного NPC, и человек,
  говорящий сам, брал реплику из общего котла, тогда как тот же человек в диалоге отвечал
  по обстановке. Замер жилого этажа: было 30 реплик в минуту, из них бытовых ДВЕ — этаж
  говорил только о бое; стало 35, из них бытовых треть.
- **Цель никогда не лежит в бетоне (с 2026-08-24).** Два источника цели отдавали
  непроходимую клетку, а поиск пути на такой цели возвращает пустой путь и роняет дело
  МОЛЧА. Стратегический ярус восприятия отдавал геометрический центр ячейки 16×16 — тот в
  стене на 61% жилого этажа и 99.7% квартир, где шаг сетки квартир совпал с шагом яруса;
  теперь ячейка отдаёт своего ПРЕДСТАВИТЕЛЯ (ближайшую к центру проходимую клетку,
  запекается тем же проходом, 16 КиБ). Доля назначенных маршрутов: жилой 37% → 96%,
  квартиры 0% → 97%, министерство 40% → 98%. Ярус комнаты отдавал центр комнаты вслепую в
  обеих запасных ветках; теперь до него идут восемь проб последовательности R2, и центр
  тоже проверяется. Замки — `tests/target-not-in-concrete.test.ts`.
- **Невидимых стен не бывает (с 2026-08-24).** Клетка `Cell.DOOR` без записи в
  `world.doors` сплошна навсегда, при том что навигация считает её проходимой: открыть
  нельзя, сломать нельзя, увидеть нечем. На дизайн-этажах таких клеток ноль, замок
  `tests/phantom-doors.test.ts` ловит регресс генератора. Попутно вскрылось, что сцена
  стенда `corridor` была запечатана именно так, и все снятые с неё числа описывали мир, из
  которого нельзя выйти (застревание в сцене после починки 25.3% → 3.5%).

За ИГРОКА вступается тот, чьё личное отношение к нему дошло до общего порога дружбы: его фракция синтетическая и других членов не имеет, поэтому «свои» для него читаются личным каналом (по замеру — 84% дружественных фракций, а не все). ### Мир без наблюдателя: караваны и фракционные события

- **Караваны (`systems/caravans.ts`)**: судьба малого каравана под самосбором читается из факта мира под самим караваном (`world.fog > 100` — тот же порог, по которому самосбор считает клетку своей), а не из расстояния до игрока. Рейс на **неактивном** этаже не объявляется разграбленным за то, что игрок уехал лифтом: там нет ни позиции, ни фронтов, и рейс просто идёт дальше. Точка сборки каравана берётся от подходящего NPC на активном этаже (`smallCaravanMemberEligible`); нет такого человека — спавн отменяется целиком.
- **Фракционные события (`systems/faction_events.ts`)**: сектор выбирается взвешенно по спорной территории (`zone.territoryCounts`), живому населению сектора и уровню опасности, делённо на свежую фракционную активность (`getRecentEvents`) — политика расползается по дому, а не бьёт в одну точку. Якорь события — штаб фракции в секторе, иначе центр сектора; непроходимая клетка ищется заново внутри того же сектора. Позиция игрока задаёт сектор только в отладочном `forceFactionEvent`. `sawPlayer` у стычки ставится покадровым наблюдением, а не в момент спавна.
- **Экстренное укрытие (`systems/ai/npc_emergency.ts`)**: комната оценивается по тому, **кто в ней уже сидит**, а не по тому, там ли игрок. Враждебный обитатель (личный по графу Демоса или фракционный, через `isHostile`) даёт −18, дружественный по матрице фракций +6, незнакомый −2. Личный сид укрытия `npcEmergencyJitter` больше не подмешивает `playerRelation`: сид складывается только из того, чем NPC является сам.
- **Тактический профиль (`systems/ai/tactics.ts`)**: игрок больше не дописывается в факты восприятия после ограниченного `scanCap` запроса — он лежит в том же индексе актёров и обязан пробиваться сквозь кап наравне со всеми. Иначе в толпе монстр всегда видел игрока и терял соседей. Поле `sawPlayer` удалено, параметра `player` у `runActorTactic` нет.
- **Слух об аномалии лифта (`systems/floor_instances.ts`)**: `spreadElevatorInstanceRumor` расходится от **места** события — координаты лифта, где щёлкнула аномалия, — а не от игрока: ехать в нём мог кто угодно.
- **Контекст речи (`systems/context.ts`)**: поле `playerDistance` из `ContextSnapshot` удалено; расстояние до игрока больше не входит в выбор реплики.

### Речь NPC: единое ядро Маркова и авторский корпус (`systems/markov_text.ts`, `data/markov_text.ts`)

Речь идёт через один роутер (`systems/speech_router.ts`) и один источник на выбор: `locked_author_text` (сюжетная строка дословно), `generated_markov` (обход графа) и `curated_pool` (точная строка сценариста из корпуса домена).

- **Точка сборки доменов реально читается.** `MARKOV_DOMAINS` / `MARKOV_TEMPLATES` — адрес авторского текста: `selectCuratedCorpusLine()` берёт домены, разрешающие запрошенный интент, и выбирает строку по полосам контекста. Полосы строки — условие И, а не сумма баллов: реплика, размеченная `event`+`faction`, молчит там, где драки не было. Отбор — верхний ярус по числу совпавших полос (адресная реплика профессии бьёт общую реплику домена), внутри яруса — вероятностный по весу строки, через общий `rng()`.
- **Полоса контекста строится из тега целиком, его префиксов и его сегментов** (`need.food.low` → `need`, `food`, `low`, `need.food`), а профессия и фракция приходят числами и дают полосу вида `occupation.5` / `faction.1`. Поэтому запись корпуса, размеченная ключом того же перечисления, доезжает до своего NPC, а не до соседа по этажу.
- **Домены**: 12, включая `occupations` (профессия — такая же полоса контекста, как нужда или фракция). Корпус реестра — **873 строки** против 305 прежних: молчаливая обрезка (`cap = 14` на корпус, `capPerKey = 5` на ключ) снята, строку роняет только чёрный список тона.
- **Замок** — `tests/markov-corpus-reachability.test.ts`: тест не перечисляет корпуса поимённо, а берёт все экспорты модуля, похожие на корпус реплик, и требует, чтобы каждая живая строка лежала в каком-нибудь домене. Массив, написанный и не вписанный в реестр, валит тест сам.

### Настольные игры (`systems/tabletop.ts`, `render/tabletop_ui.ts`)

Девять настолок: дурак, кости, домино, шашки, покер (холдем хедз-ап), шахматы, го 9×9, длинные нарды, морской бой. Каждая — самодостаточный модуль: свои правила, свой ИИ, своя графика. Общей графики между модулями нет намеренно — перекрасить покер нельзя, задев дурака.

- **Реестр вместо прошивки**. Игра описывается одной регистрацией: `registerTabletopGame` в `systems/<игра>.ts` (правила, предмет-условие, ставка, ввод, снимок, кооп-вид) и `registerTabletopPanel` в `render/<игра>_ui.ts` (панель). Реестр разрезан по слоям надвое, потому что `systems/` лежит ниже `render/`. `main.ts` ни одной настолки по имени не знает — вся диспетчеризация идёт через `openTabletopGameFor(npcId)`.
- **Кооп-активность выводится автоматически**: зарегистрированная игра сразу доступна и против NPC, и за столом с живым игроком, без второй регистрации.
- **Меню — группа, а не стена**. Пункт `Сыграть (N)` в меню NPC разворачивается в список доступных игр; N — сколько наборов реально на руках у двоих. Группировка универсальна: любая опция объявляет `group`, и одинаковые схлопываются в одну строку с вложенным списком. Пустая группа не показывается.
- **Условие — предмет**: колода, кости, коробка домино, шашки, шахматы, набор го, нарды, блокнот морского боя. Достаточно, чтобы набор был у одного из двоих. Покер делит колоду с дураком.
- **Партия детерминирована от сида**: раздача, броски, расстановка флота и выбор залпа идут через общий `rng()`, а не через косметический `mathRng`. Ставка уходит в `player.money`, поэтому недетерминированная партия означала бы сейв-скам и расхождение хоста с пиром в онлайне. То же правило накрыло игровой автомат и цвет мела. Замок — `tests/games-deterministic.test.ts`.

### Сцены этажа (`systems/cinematics.ts`, `systems/cinematic_actors.ts`, `systems/camera.ts`)

Сцена — это **объявление, а не код**: этаж перечисляет актёров и такты, а общий проигрыватель их отыгрывает. Своего боя, своей смерти и своего расселения у сцены нет — она ставит людей, даёт им слово и наводит камеру, всё остальное делают те же системы, что и без зрителя.

- **Реестр**: `registerFloorScene({ id, floorKey, trigger, anchorRoomAlias, actors, beats, maxSeconds })`. Якорь сцены — **именованная комната** по `defId` (тот же точный поиск, что у `named_rooms`), а не координата.
- **Триггеры**: `first_visit` (первый приход на этаж за прогон), `event` (публикация события мира с типом и опциональным тегом, через `registerWorldEventObserver`), `manual` (сюжетный шаг или отладка через `requestFloorScene(id)`).
- **Такты**: `fly` (пролёт; без `look` кадр смотрит ПО КУРСУ и поворачивает вместе с ломаной, с `look` — не отпускает субъекта), `orbit` (облёт точки), `say` (бабл над головой; без `seconds` длительность выводится из длины строки), `pause`, `awaitDeath` (ЖДЁТ смерти роли с верхней границей `timeout`, а не устраивает её), `defect` (смена фракции + сброс кэша боевой цели), `materialize`, `release` (снять поводок), `moveTo` (отправить роли своими ногами в точку — ВЕЙПОЙНТ, цель ставится один раз), `walkOut` (уйти к лифту и с этажа; с этажа никого не снимают, пока сцена идёт, и ещё выдержку после её конца), `depart` (мгновенно, годится только вне кадра). Такта «строка в журнал» НЕТ намеренно: сцену смотрят, а не читают.
- **Точка кадра** (`SceneSpot`): смещение от якоря `{ ox, oy }`, центр масс роли `{ role }` либо `{ speaker: true }` — тот, кто сказал последнюю реплику. Точка внимания живёт до следующего такта камеры и пересчитывается КАЖДЫЙ кадр, включая реплики и паузы: за фразу человек уходит на несколько клеток.
- **Актёры**: `packageId` зовёт уже живущего на этаже авторского NPC (`extractNpcForScene`), `source: 'alife'` черпает из пула A-Life (личностей не создаёт), `monster` ставит тварей из общего реестра `MONSTERS`, иначе массовка спавнится с `role: NpcRole.CINEMATIC_ACTOR`. Расстановка — кучками со смещёнными центрами (ровный веер спирали читается как строй по линейке), либо `ring` — кольцом на радиусе для наплыва со всех сторон; место на кольце проверяется на связность с точкой.
- **Цикл AI не выключается для актёров сцены (с 2026-08-22).** Роль `CINEMATIC_ACTOR` больше не исключает человека из прохода AI: она означает «на посту», а не «выключен». Раньше исключала, и это давало вторую, несимулируемую породу людей — гражданский бил ликвидатора в строю, а тот не отвечал, потому что его AI не запускался. Держит актёра поводок к его посту (`cinematicState.postX/postY`, `SCENE_POST_LEASH = 1.5`); `release`, `moveTo` и `walkOut` снимают роль, и дальше действует общий поводок сцены. Замок — `tests/unanswered-hits.test.ts` и `tests/cinematic_actors.test.ts`.
- **Прибор «кого бьют безответно»** (`tests/unanswered-hits.test.ts`): следит за живым этажом покадрово, ловит убыль здоровья и весь срок выдержки смотрит, ответил ли пострадавший; не ответившие раскладываются по причинам — обидчик погиб, убежал, занят другим, память боевая и человек не шелохнулся. На коллекторах за 45 секунд 1847 попаданий и **ноль безответных**.
- **Поводок**: `leash` у сцены держит каст в пределах места действия, `leash` у актёра — свой, короче; ушедшего возвращает цель `GOTO` со снятием боевой цели на время возврата. Тому, на ком стоит кадр, нужен свой короткий: общий заведомо шире комнаты. Проверка идёт **каждый кадр**, и снимаются ВСЕ ТРИ канала поиска врага: взятая цель, память об ударе (`clearCombatThreat`) и свежий скан (`ai.combatScanCd` на полсекунды). Одной цели мало — память возвращала бойца в драку тем же кадром, а скан находил новую тварь заново. Замерено на форпосте: было 3.6 в среднем и до 7.5 в худшем, стало 2.05 четыре прогона подряд при поводке в две клетки. Обход каста стоит взгляда в индекс по id и квадрата расстояния на актёра, так что три сотни смотра министерства он выдерживает.
- **Проигрыватель** живёт на `registerContentRuntimeHook` (фаза `floor_activity`). Флаг `state.sceneLock` блокирует движение, взаимодействие и огонь игрока (`main.ts`), и он же ДАЁТ ИГРОКУ НЕУЯЗВИМОСТЬ тем же путём, что трейлер-режим (`isDebugOnePunchManEnabled`): кадр не принадлежит игроку, убивать его нечестно по построению, а смерть под сценой рвёт саму сцену. Снимается вместе с замком, и он же снимает обычный сброс кинематографической камеры по нажатию клавиши: сцена владеет кадром до своего последнего такта — **или до тех пор, пока игрок не заберёт кадр себе** (см. следующий пункт).
- **Игрок вправе забрать кадр, не обрывая сцену (с 2026-08-24).** Клавиша «принять» (`Enter` по умолчанию, берётся из реестра управления) снимает `sceneLock`: возвращаются камера, ввод, HUD — и НЕУЯЗВИМОСТЬ ТОЖЕ СНИМАЕТСЯ, намеренно («вышел из кадра — принял риск»). Сцена при этом НЕ обрывается: актёры, реплики и такты доигрывают до своего логического конца, а камерные такты становятся пустыми через `sceneOwnedCamera()`, отдающий `null` после отпускания. Без этого сцена ВИСЛА БЫ до `maxSeconds`: такт `fly` ждёт прилёта камеры, которую больше никто не ведёт. Клавиатура, а не мышь, — потому что кнопки мыши доходят до игрового ввода только при захваченном указателе, и игрок, отпустивший указатель, остался бы в сцене без выхода. Нажатие съедается (иначе тот же кадр открыл бы им меню) и взводится ОТПУСКАНИЕМ: зажатая с порога клавиша не снимает сцену молча. Подсказка рисуется в нижней полосе кадра. Замок — `tests/floor-scene-release.test.ts`. Камера приходит **инъекцией** через `bindSceneCamera(runtimeCamera)` — рантайм-камера принадлежит входной точке, импорт из `systems/` завёл бы ребро `systems → main`.
- **Кадр вместо HUD**: при `sceneLock` рисуется `drawSceneOverlay` (`render/hud.ts`) — чёрные полосы сверху и снизу по `SCENE_LETTERBOX_FRACTION = 0.1` высоты плюс баблы речи. Баблы проецируются от **камеры** (`SpeechBubbleView`), а не от игрока: во время сцены кадр держится в десятках клеток от него, и от игрока речь актёров рисовалась бы мимо экрана. Оверлей ничего не решает, только читает состояние.
- **Возврат**: исчерпав такты (или `maxSeconds`), камера ЛЕТИТ обратно к игроку и только потом отдаёт управление; при обрыве маршрута срабатывает потолок ожидания.
- **Персистенс**: id уже сыгранных сцен уходят в сейв секцией `playedScenes` (кап `MAX_PLAYED_SCENES = 32`, id обрезается до 64 символов).
- **Обрыв снаружи**: `abortFloorScene(state, entities)` снимает замок, отпускает актёров с их собственными ролями и возвращает камеру игроку. Зовётся на всех трёх границах, где сцена теряет свой мир: продолжение после смерти, `switchFloor` и `loadGame` (плюс `resetFloorScenes` при новой игре). Порядок значим: на смене этажа обрыв идёт ДО складывания A-Life (иначе актёры уедут в записи с ролью сцены, которой на новом этаже нет), а при загрузке — до `restoreFloorScenesFromSave`. Без обрыва данные не портятся — навсегда запирается управление.
- **Актёр сцены — не тело для продолжения после смерти**: `randomDeathContinuationNpc` (`main.ts`) их пропускает, потому что такт `depart` вправе увести актёра с этажа, и вместе с ним уехал бы игрок. Симметрично `depart` не трогает `isPlayerEntity`: тот, кто стал игроком посреди сцены, не вынимается из мира тактом. Роль сцены снимается ДО записи в A-Life, а сама запись нормализует её ещё раз (`alife.md`, `save.md`).
- **Замки краёв** — `tests/floor-scene-edges.test.ts`.
- **Отладка**: команды `СЦЕНА: запустить по id` и `СЦЕНЫ: список`. Запуск по id забывает сыгранное, чтобы одну сцену можно было посмотреть дважды; играющую сцену команда не трогает.
- **Контракт авторства сцен — `cutscene.md`**: якорь, актёры, словарь тактов, ловушки (радиус облёта считать от комнаты, выводить субъекта на середину перед облётом, не проверять исход боя в замках).
- **Министерство несёт 2000 служащих** при полном бюджете акторов (было 1000) и ставит их В КОМНАТЫ: место ищется по `roomMap >= 0`, и лишь на последних попытках берётся любая свободная клетка. Было 201 человек в комнатах из 1070, стало 1191 из 2077. Плотность 2.67 → 5.2 человека на тысячу проходимых клеток, вровень с жилым (5.34) и квартирами (4.93): при прежней тысяче, размазанной по мраморным залам, ведомство читалось пустым. `npcMult` профиля сведён с этим числом (0.4 → 1.28) — прежние 0.4 обещали 627 человек при фактической тысяче, и общий шаг населения не добавлял никого, то есть ручка выглядела живой, будучи мёртвой.
- **Сцен в игре восемь (2026-08-27, было три).** Пять добавлены одной сессией и ни одна не потребовала правок проигрывателя, `main.ts` или ядра: новый файл в `src/gen/<этаж>/` с `registerFloorScene()` на верхнем уровне, строка `import './<сцена>'` в `content_manifest.ts` (или именованный импорт из генератора) и `defId` на комнате-якоре. Полный список id: `living_prologue`, `maintenance_forpost_defense`, `ministry_garrison_parade`, `liquidatorbase_arena_duel`, `ministry_zaslonov_betrayal`, `slime_nii_institute_tour`, `hell_garrison_entry`, `perevalka_four_doors`.
- **Первые в игре сцены на событийном триггере — `ministry_zaslonov_betrayal` и `hell_garrison_entry`.** Механизм `{ kind: 'event', eventType, tag }` существовал с самого начала, применений было ноль: все три прежние сцены висели на `first_visit`. Правок проигрывателя не потребовалось. **Кадр разгоняется и тормозит накатом (с 2026-08-22).** Три величины кадра назначались ПРЯМО и оттого дёргались на каждой смене такта: скорость (переход 20 → 5 читался толчком), высота (проезд с 1.1 на 1.8 — вертикальным скачком) и сам ход, обрывавшийся ровно на последнем узле маршрута. Теперь такт задаёт ЦЕЛЬ, а кадр подходит к ней той же экспонентой, что и радиус облёта (`CINEMATIC_ORBIT_EASE`) — одна манера двигаться на все поводы. Подъезд к точке идёт накатом по ОСТАТКУ ЛОМАНОЙ, а не по прямой до конца (на дороге буквой П камера бывает в двух клетках от цели, пройдя половину пути), с нижней полкой `CINEMATIC_GLIDE_FLOOR`: без неё замедление становится асимптотой и прибытия, которого ждёт такт, не наступает. Накат не действует на вынужденный ход и на дорогу из одного узла — там ломаной нет, и замедлять нечего.

**Тело игрока видно, когда кадр отвязан** (с 2026-08-22). Спрайтовый проход выбрасывал игрока одной безусловной строкой, и во всех четырёх отвязанных режимах — сцена этажа, смерть, свободная камера, трейлер — человек оставался невидимкой; заметнее всего это было по его собственному баблу речи, висевшему над пустым местом. Теперь `renderSpritesGL` получает `drawPlayerBody = camera.mode !== 'player'`: в первом лице всё как было, в отвязанном кадре тело рисуется. Одето оно как сетевой пир (`Occupation.TRAVELER`, `ONLINE_PLAYER_SPRITE_SCALE`) — при `sprite: 0` игрок выходил ДОМОХОЗЯЙКОЙ в полный рост, вдвое выше стоящего рядом пира.

**Живность привязана к миру и к свету** (с 2026-08-22, `render/critters_pass.ts`). Две поломки одного корня. Высота глаза была захардкожена половиной (`uResolution.y / (ty * 2.0)`), то есть ошибка по вертикали равна `(0.5 − высота)·H/ty` — крысы висели в воздухе и ходили вместе с камерой, потому что её высота не постоянна ни секунды: покачивание при ходьбе, приседание, дыхание кадра в сцене, а в кинематографическом режиме наклон и вовсе выводится из высоты. Теперь проход получает `camHeight` и считает `footY` той же арифметикой, что спрайты и пол раскастера, а квад опирается на НОГИ, а не серединой на точку. Свет: прибавка за фонарь была всенаправленной (до 0.95 на всё в радиусе одиннадцати клеток) и вместе с ближним светом упиралась в потолок клэмпа раньше, чем успевал сказаться запечённый свет — живность светилась одинаково хоть под лампой, хоть в темноте. Фонарь стал лучом; вне луча яркость снова решает лампа. **Тот же дефект остался у капель крови** (`renderParticlesGL` принимает `_camHeight` и не использует его) — записано в `problems.md`.

Режиссёрская камера (`systems/camera.ts`, режим `cinematic`) поддерживает точку внимания (`lookAt`), орбиту вокруг неё, удержание кадра (`hold`), плавную целевую высоту с обрезкой по потолку клетки (`world.ceilHeight`, под открытым небом обрезки нет) и маршрут по проходимым клеткам (`routeCinematicCamera` через `bfsPath`). Отгруженные правила кадра:

- **Допуск на узел — половина подклетки** (`0.5 / PATH_BLOCKER_SUBDIV`). Допуск шире шага сетки означает, что камера объявляет пройденными сразу несколько узлов и идёт к дальнему по хорде, то есть сквозь простенок.
- **Курс берётся с точки в трёх клетках впереди** по ломаной, а не с ближайшего узла: направление на соседний узел скачет, и кадр дёргается вместо поворота.
- **Потолок скорости разворота** 2 рад/с: смена субъекта одной экспонентой давала хлыст.
- **Замков для камеры не существует**: `cameraBlocked` считает `Cell.DOOR` проходимой в любом состоянии, а маршрут собирается ЧЕРЕЗ ДВЕРИ с обоих концов — запирающая створка стоит там, где заперто, а не там, где кадр.
- **Дороги нет — идёт напрямую своей же скоростью**, а не переносится прыжком: перескок заметен тем сильнее, чем короче остаток.
- **Зазор от стен на покое** (треть клетки): в пролёте зазор не действует намеренно — он отталкивал бы кадр ровно настолько, насколько тот продвинулся, и признак «дороги нет» не срабатывал бы никогда.
- **Облёт идёт к точке круга ходом**, а не назначается ею; радиус обрезается первой преградой на луче от актёров и подтягивается плавно; запас хода растёт вместе с ходом субъекта, но не больше шага человека.

Замки: `tests/camera.test.ts` (механика), `tests/prologue-camera-flight.test.ts` и `tests/prologue-scene-camera.test.ts` (пролёт и вся сцена пролога покадрово), `tests/forpost-defense-scene.test.ts` (вторая сцена на трёх сидах: волны, связность, перескоки, доля кадров у стены, удержание командира).

- **Спрайты занятий**: `NPC_SPRITE_GENERATORS` покрывает перечисление `Occupation` целиком (23 записи), индекс равен значению занятия. Раньше лист был шириной 18, и хвост занятий садился на диапазон авторских личностей: уборщица рисовалась Ветераном Степанычем, работница 69-го — Гордоном Фрименом, инженер — Мадокой, учитель — Пахомом. Замок — `tests/sprite-occupation-space.test.ts`.
- **Плоские следы** (`systems/surface_marks.ts`): потолок `SURFACE_MAP_MAX_CELLS = 16384` — это ПАМЯТЬ (килобайт на клетку), а не размер атласа рендера. Кандидаты в атлас отсеиваются по дальности (`buildSurfaceData`), поэтому стоимость пересборки не зависит от размера карты. Дойдя до потолка, уходит самое ДАЛЬНЕЕ от свежего следа, а не самое старое: прежнее правило на бою стирало кровь, которой секунда от роду. Куски мяса считают другое (мешевые экземпляры) и держат свой потолок `GORE_CELL_MAX` в `systems/blood_fx.ts`.

- **Отношение — это число, метка выводится**: единственная точка записи графа Демоса (`setEdgeAtSlot`) снимает биты «друг/враг» с переданных флагов и ставит их заново по числу; род связи (родитель, партнёр, коллега, должник, соперник) объявляется и не выводится. Ручная выдача для авторских личностей задаёт ЧИСЛО, метка идёт следом. Замок — `tests/demos-relation-tag-derived.test.ts`.

### Онлайн-кооп «в гостях у хоста» (`systems/online_protocol.ts`, `online_client.ts`)

Опциональный режим поверх Cloudflare-релея (Durable Object `FloorRoomDO`, комнаты-коды, хост + до 3 гостей). Локальная игра полностью работает без него. Запуск — команды `/host` и `/join CODE` в чате НЕТ-СФЕРЫ.

- **Хост-авторитет (протокол v2)**: хост владеет актором гостя целиком (инвентарь, HP, магазин, деньги, потребности, RPG). Гость шлёт позицию 20 Гц и нумерованные интенты (выстрел с melee hit-claim, перезарядка, инструмент, предмет, дроп, контейнер, interact); хост отвечает одним пакетом `host_state` 8 Гц: entity sync (AOI 32 клетки/кап 64), авторитетное эхо актора, двери, звуковые fx, патчи геометрии, live-обновления открытых контейнеров и торговцев.
- **Гость приносит своего персонажа** из сейва; домой добыча возвращается **только эвакуацией лифтом живым**. Смерть в гостях — домашний сейв нетронут, труп с лутом остаётся у хоста. Сейв гостя в чужом мире заблокирован.
- **Полный этаж вместе**: лифт хоста и пост-самосборный ститч переносят гостей (полный ре-снапшот этажа); самосбор при подключённых гостях работает — фронты стримятся клеточными патчами. Меню хоста при живых гостях мир не паузит.
- **NPC для гостя**: диалог (реплики генерит хост) и полная торговля (гость исполняет локальный торговый код, хост применяет материальный итог с клампом — relaxed-trust по `online.md`). Квесты и кастомные NPC-опции гостю пока недоступны.
- **Кооп-столы между игроками (`systems/coop_session.ts`)**: `E` по другому игроку открывает то же NPC-меню, урезанное до применимого к живому человеку — четыре настольные игры и обмен. Любой пункт становится **приглашением**: второму приходит панель внизу экрана, ЛКМ принять / ПКМ отклонить, без ответа приглашение гаснет за 20 секунд. Согласие сажает обоих за один стол, который целиком живёт на хосте: он держит партию, двигает деньги и шлёт каждому вид его собственного кресла (своя рука, у соперника — только число карт). Пир шлёт лишь нажатия своего сиденья, поэтому подделать выигрыш нельзя.
  - **Игры**: дурак, кости, домино, шашки, покер, шахматы, го, нарды, морской бой. Модули игр не переписаны — за сторону `'npc'` просто перестаёт ходить ИИ, и ход ждёт второго человека. Шашки и шахматы разворачивают доску на 180° для второго кресла; морской бой отдаёт чужое поле только как отстрелянные клетки. Ставка — 10% от денег **беднейшего** из двоих, чтобы её покрыли оба. Выход из-за стола = сдача: ставка уходит оставшемуся.
  - **Обмен (`systems/coop_barter.ts`)**: две корзины, никто ничего не оценивает. Ничего не двигается, пока **оба** не подтвердят; правка любой корзины снимает оба подтверждения. Обмен исполняется один раз на хосте с клампом по реально имеющемуся. Брошенный обмен не двигает ничего — ставки в нём нет.
  - **Сидящие за столом не двигаются, но и не защищены**: партия отнимает ноги (`movePlayer`), а не неуязвимость. Монстр или чужой игрок может убить обоих прямо за доской — смерть засчитывается сдачей, ставка уходит выжившему, стол закрывается. Садиться играть в опасном месте — осознанный риск игрока. Мир вокруг продолжает симуляцию: чужая партия никого больше не паузит.
  - Стол на хосте один: игры держат по одному модульному экземпляру, второе приглашение получает «Стол занят».
- Дизайн-контур, экономика запросов и известные ограничения — `online.md`, секция «SHIPPED: Protocol v2».

### Геометрия панелей: одна раскладка на отрисовку и на тап (`render/ui_layout.ts`)

Каждая полноэкранная панель считает свою раскладку в одной функции, и рисование с тач-хит-тестом берут её оттуда же. Считать координаты второй раз в `main.ts` запрещено: расхождение даёт нажатие мимо нарисованной строки.

- **Диалог NPC (`npcMenuLayout`)**: коробка 440x320 условных единиц, масштаб упирается в канвас (`w/464`, `h/344`) — всё внутри размечено в этих единицах, поэтому обрезка коробки без обрезки масштаба ломала бы каждое смещение. Список опций показывается окном вокруг выбранной строки (`firstRow` / `visibleRows`) с маркерами `▲`/`▼`; настольная игра рисует себя сама через `registerTabletopPanel`, получая ту же коробку.
- **Инвентарь (`fullscreenInventoryLayout`)**: сетка 8x8 берёт всю высоту под строкой заголовка (резерв 18 текстовых единиц) и не шире половины канваса — остаток ширины принадлежит правой колонке с описанием предмета. Масштаб сетки и масштаб текста разные величины: `scale` — сетка, `textScale` — текст правой колонки.
- **Торговый стол (`tradeMenuGridLayout`, `tradePanelOrigin`)**: три бокса в ряд — ваш инвентарь, общий стол, инвентарь NPC — и полоса сделки под ними. Стол разделён пополам: левая половина `ДАЮ`, правая `БЕРУ`, ширина половины выведена из `TRADE_OFFER_SLOT_CAP`, поэтому у каждой выставленной стопки есть клетка. Курсор живёт в пространстве `(сторона, слот)`; стол — это вид на обе корзины, а не третья корзина.
- **Контейнер (`containerMenuGridLayout`)**: доступ, кража и статус цеха идут строками шапки, ширину делят только две сетки.

### Система сохранений и Политика отсутствия совместимости (Save Policy)

- **Ключ хранения**: Игровой прогресс сохраняется в `localStorage` браузера под ключом `gigahrush_save`.
- **Версия формы**: Авторитетная версия формы сохранения определяется константой `SAVE_SHAPE_VERSION` в `src/core/save_shape.ts` (лист без зависимостей; `save_runtime.ts` её только импортирует).
- **Снапшот активного этажа (дельта)**: В сейв попадает только текущий активный этаж — компактной дельтой поверх заново сгенерированной по `(runSeed, z)` базы (XOR-геометрия + разреженные diff комнат/дверей; сущности, контейнеры и зоны абсолютны), что укладывает даже плотный этаж в лимит `localStorage`. Хэш-страж `baseHash` ловит дрейф генератора между сохранением и загрузкой и откатывает к честной регенерации, а не к порче сетки. Детали — в [save.md](save.md).
- **Транзиентность и Спрайты Предметов**:
  - Визуалы предметов в мире и инвентаре процедуры вычисляются по `defId` в `src/render/item_sprites.ts` (не требуя хранения спрайт-ID в файлах сохранения).
  - Рантайм-режим камеры и интерполяция являются транзиентными (сбрасываются при смене этажа и загрузке), а угол обзора игрока и настройки FOV сохраняются.
  - Сыгранные **сцены этажа** транзиентными не являются: их id уходят в секцию `playedScenes` (кап 32), иначе пролог играл бы заново после каждой загрузки. Подробности — [save.md](save.md).
- **ПОЛИТИКА ОТСУТСТВИЯ СОВМЕСТИМОСТИ (No Backward Save Compatibility)**:
  - В проекте ГИГАХРУЩ нет поддержки старых сохранений. Старые сейвы являются одноразовыми (`disposable`).
  - Запрещено писать костыли миграции, адаптеры старых полей или код обратной совместимости для прошлых версий сохранений.
  - Если изменение затрагивает структуру пейлоада сохранения, следует повысить `SAVE_SHAPE_VERSION` и отклонять устаревшие сохранения нативно.

## 6. Сюжет, Квесты и Локации (Story Chain, Quests & POIs)

### Стартовая зона (`LIVING`, z=0)

Игрок появляется в **Актовом зале** (защищенный блок с проектором, слайдами и тумбочкой). Рядом находится **Оружейная** сержанта Баринова с мишенями. Далее располагаются лаборатория Якова Давидовича и логовище Ваньки Банчиного.

Проектор Актового зала воспроизводит 8 кадров инструкций (приветствие, трудовые лозунги, правила гермодверей и фиолетовый туман).

В сорока клетках от Актового стоит **Разборный зал** (`prologue_hall`, `LIVING_NAMED_ROOMS`) — большой зал, куда сносят последствия самосбора. При первом приходе на жилой этаж за прогон там играет сцена `living_prologue`: полковник Гаревой ведёт разбор, Стрелок переходит на сторону Диких вместе с половиной взвода, зал раскалывается. Игрок этого не видит своими глазами — камера летит туда сама, ввод на время сцены заблокирован (`state.sceneLock`). Исход не предрешён: после такта `release` дерутся обычные системы. Зал роется в `gen/living/index.ts` шагом `B0b` — после зонных модулей и до хаб-геометрии — и добирает проход волной снаружи, обходя `aptMask` и лифты; последняя мера при кольце чужих квартир — прямой прорез к `tutor_hall`. Сюжетные слоты `prologue_colonel` и `strelok` дописаны **в конец** `PLOT_NPC_ID_ORDER` — сейв хранит числа.

**Блокада — гейт физический, а не шаг журнала.** Отдельного задания «пройти Перевалку» в цепочке нет: Блинков и министр только объясняют, почему низ закрыт, а упирается игрок в запертые лифты Перевалки (Z=-16) и решает вопрос с одной из четырёх баз — квестом, боем, покупкой ключа или пробивным зарядом. Ад переехал в поздний гейм, ПОСЛЕ руны и НИИ слизи.

**Шаг 14 — единственный giverless-шаг в середине цепочки, и он FETCH намеренно.** Убийство генерала Заслонова шагом цепочки НЕ является: после такта `defect` он просто враждебен, игрок дерётся по обычным правилам, руна выпадает из его инвентаря вместе со всем остальным, и подбор закрывает шаг. Ни одной скриптовой развязки. `sourceLabel: 'Министерство'`.

**Виды трёх образцов НИИ разыгрываются жребием, а не записаны в данных.** `plotSampleKindsForSeed(seed)` (`src/data/plot.ts`) берёт три РАЗНЫХ вида, взвешенно по `rankMonsterEcology` (нулевой вес отсеивается ею самой, «мебельные» виды в жребий не попадают) и детерминированно по сиду прогона; `applyPlotSampleLottery` вписывает вид, описание и подсказку в шаги, а зовётся из `generatePlotQuest` — только там виден `state` и русские имена монстров. Значение уезжает в `Quest.targetMonsterKind`, поэтому переживает загрузку. Подсказки, где искать, нет намеренно: это охота, а убийство засчитывается на любом этаже. Три шага находятся **по метке** `eventTags: ['nii','nii_sample','black_rune']`, а не по номеру. Замок — `tests/plot-chain-samples.test.ts`.

**Мир меняется после снятия руны.** `src/gen/maintenance/garrison_reinforcement.ts` слушает `quest_completed` с ПАРОЙ тегов `zaslonov_betrayal` + `black_rune` (во всей цепочке эта пара принадлежит ровно одному шагу; номеров шагов в модуле нет) и переселяет волну ликвидаторов с Базы Ликвидаторов в гарнизон Громного через `migrateAlifePopulation` — это перевозка существующих личностей, а не спавн: донор редеет ровно на приехавших. Однократность держит список `alife.migrations` в сейве, а не свой флаг. Замок — `tests/maintenance-garrison-reinforcement.test.ts`.

**Перестановка цепочки сломала форму сейва:** `Quest.plotStepIndex` уезжает числом и на загрузке не ремапится, поэтому `SAVE_SHAPE_VERSION` поднят 27 → 28 и старые сейвы отвергаются. Тем же бампом закрыты два новых поля верхнего уровня в секции `alife` (см. `save.md`). Новые слоты личностей (`blinkov`, `nii_gushchin`) дописаны **в конец** `PLOT_NPC_ID_ORDER`.

Последние три шага **не имеют дающего**: Пустота безлюдна, их выдаёт сама цепочка и закрывает дело, а не сдача. Тем же путём идёт шаг, чей дающий погиб, — при условии, что у игрока на руках его дневник.

**Смерть сюжетного NPC не запирает цепочку.** Любой сюжетный NPC роняет при смерти **дневник** (`npc_diary`, `ItemType.NOTE`, владелец в `Item.data.plotNpcId`). Дневник в рюкзаке заменяет разговор с покойным: выдаёт его шаг как `giverless`, разрешает закрыть его FETCH/KILL без сдачи и закрывает TALK, где он цель. Если дневника нет, а цепочка в него упёрлась, он воплощается заново на месте гибели — координаты и этаж смерти хранит запись A-Life и переживает сейв через компактный оверрайд мёртвого слота. Новой секции сейва нет, `SAVE_SHAPE_VERSION` не тронут: право говорить за покойного носит сам предмет, а инвентарь и так сохраняется. Код: `src/systems/plot_trace.ts`, три точки чтения в `src/systems/quests.ts`.

**Личность адресуется слотом, а не номером сущности** (с 2026-08-22). У авторского NPC `alifeId` — номер его слота, `entity.id` — обычный номер тела из общего счётчика; раньше доставка выдавала оба равными, и около ста мест по коду читали `entity.id` там, где имели в виду человека. Живой человек по слоту ищется через `EntityIndex.byAlifeId`, принадлежность к сюжетным — через `isPlotNpc` (`data/plot.ts`). Поле `Quest.giverId` (и `targetNpcId`) по природе двух видов: **авторское** задание хранит слот, **процедурное и контрактное** — номер живой сущности, потому что личности за ним нет; различает их `questAddressesBySlot()`, и спросить обязан каждый читатель — перебор «сначала по номеру, потом по слоту» находит чужого. Сейв не двигался: слоты как числа лежали в этих полях и раньше. Замки: `tests/entity-ids.test.ts` (авторский человек носит слот в `alifeId`, а номер сущности — обычный) и проверка в `npm run check:invariants`, запрещающая читать слот из `.id` сущности.

### Создание Авторского Дизайн-Этажа (`design_floors`)

Каждый четный этаж (`Z % 2 === 0`) — это отдельный независимый авторский модуль со своей уникальной геометрией, правилами, атмосферой и механикой (как своя «подыгра»). Старая система отдельной генерации `story floors` упразднена: все авторские этажи выстроены по единой системе пакетов дизайн-этажей.

**Чек-лист добавления нового авторского дизайн-этажа**:
1. Добавить метаданные маршрута в `src/data/design_floors.ts` (`DESIGN_FLOOR_ROUTES`).

### Разрушаемое окружение, Арена и Мобильные опции

- **Разрушаемые баррикады и стены**: Баррикады и некоторые типы стен поддаются разрушению взрывами, тяжелым оружием или киркой.
- **Запертая дверь берётся руками, но не бесплатно и не молча (с 2026-08-27)**: обе ветки удара по преграде — гермостворка в самосборе и «нет ключа» — сведены в один `bashBlockedDoor` (`systems/interactions.ts`), и каждое нажатие `E` публикует шум ровно той же громкости, что та же дверь, открытая ручкой (обычная `severity: 2`, гермо `severity: 3` с тегом `hermetic`). Кулдаун на `E` НЕ вводился: спам стал громким, а не медленным, и на шум приходят все, кто в радиусе. Войлочная накладка здесь не тратится и не помогает — она глушит защёлку, а не удар. Заодно ожило авторское поле `Door.maxHp`: ленивая раздача здоровья перезаписывала ОБА поля, если не было ХОТЯ БЫ одного, а генератор пишет в литерале только `maxHp`, поэтому броня створки не работала НИКОГДА. Проверка ключа вынесена в общий `actorHasDoorKey` (`systems/door_state.ts`) и зовётся из обеих копий механики, включая обслуживание онлайн-пира в `main.ts`. Непроламываемых дверей при этом не появилось: бронированная створка всё равно ломается руками и оставляет настоящую дыру. Замок — `tests/door-lock-hardening.test.ts`, 7 кейсов.
- **Арена ставок**: На этаже `floor_69` и фракционных зонах действует система ставок на бои сущностей.
- **Лестница арены (с 2026-08-24)**: `systems/arena_ladder.ts` — бойцы, чемпионство и претенденты на Базе Ликвидаторов (`liquidatorbase`, Z=-12). **Боец арены — это ЛИЧНОСТЬ A-Life с флагом, а не спавн**: бит `ALIFE_FLAG_ARENA_FIGHTER` в колонке флагов, лестница строится по силе (уровень, при равенстве — запас здоровья) от слабейшего к сильнейшему. Первый ростер (8 ступеней) берёт ПО ПРЕДСТАВИТЕЛЮ МИРА НА СТУПЕНЬ: два прохода по колонке уровней ищут потолок фактической силы и раздают корзины (`selectAlifeArenaLadderIds`), 2.6–9.5 мс один раз за забег. Обе крайности замерены и отвергнуты — набор из гарнизона базы давал восемь ур.1/hp100 (гарнизон весь первого уровня), буквальный топ-8 давал восемь ур.99–100 подряд, о которые новичок разбивается на первой ступени. Сейчас лестница на трёх сидах ровная: ур. 12 → 25 → 37 → 50 → 62 → 75 → 87 → 100, вершина = потолок силы мира. Сюжетные и авторские личности исключены: смерть ступени запирала бы цепочки. Боец с чужого этажа приезжает на песок сам — `materializeAlifeArrival` перевозит запись. **Игрок дерётся сам**: пункт «Вызвать» в меню Марко Лоло выводит ступень на песок, противник получает принудительную боевую память `forceCombatThreat` с реакцией `fight` — обычный боевой AI, обходящий и матрицу фракций, и бегство. Оба под `setDuelLock`: гарнизон в поединок не вступается и удар по бойцу не считается свидетелям как нападение. Убил чемпиона — сам чемпион (`arenaChampionAlifeId = -1`), и срабатывает написанная ранее награда `grantArenaChampionRewards` (Золотой Кубок, +1500 опыта, +30 к отношению живых ликвидаторов). **Титул надо держать**: на такте 30 с с шансом 25% к чемпиону-игроку приходит претендент — уже помеченный флагом боец, а не новый человек. **Флаг редко переходит по холодной симуляции во всём мире**: тем же тактом срез в 64 личности (`forEachAlifeNpcRecordSlice`, курсор по кольцу) с шансом 0.0002 на личность, потолок — размер ростера; новых людей не рождается, закон «никакого добора фонового населения» цел, а лестница не кончается навсегда после вырезанного ростера. **Бесконечные бои с мутантами** — отдельный режим того же меню: волны растут с номером, за очищенную волну распорядитель платит; волна, которой некуда встать, закрывает песок, а не открывает кассу каждый кадр. Уход из комнаты арены и смена этажа закрывают бой. Поединок живёт ровно один. Замок — `tests/arena-ladder.test.ts` (11 тестов).
- **Фоновая живность (GPU)**: Крысы, тараканы, мухи, мошка, мокрицы и пауки рождаются в вершинном шейдере из полей мира вокруг игрока — CPU за них не платит, в сейве их нет. Мухи собираются над полем трупного запаха (`world.dangerField`, куда теперь пишут и смерть, и ранение), тараканы у плит, раковин и в темноте, мошка кружит у ламп и свечей, пауки сидят в углах из стен. Живность шарахается от игрока и гаснет вместе со светом комнаты. Набор видов задаёт этаж через `DesignFloorRenderProfile.fauna`: на Пустоте нет никого, в Мясном низу летит пепел. Переключатель в графических настройках выключает систему целиком; на тач-устройствах она теперь тоже работает, блоком поменьше.

## 8. Принципы разработки и правила оптимизации (Engineering & Performance Rules)

1. **Запрет полных сканов мира в каждом кадре**: Все тяжелые операции вычисляются по дирти-флагам, кольцевым буферам и радиусам взаимодействия.
2. **Запрет рантайм BFS во время активного геймплея**: Карта навигации, поля потоков и освещение запекаются при загрузке этажа и сшивке Самосбора — во время симуляции пересчет O(W²) запрещен. Во время Самосбора кэш навигации остается замороженным. Навигация — это 2-уровневый граф **Region-Portal HPA\*** (регионы = комнаты + кластеры `16×16`, порталы, матрица переходов `_regionNext` строится по одному BFS на регион, O(R·E)), запросы O(1). Локальная разрушаемость и постройка стен/дверей обновляют граф **инкрементально** (`patchNavigationRegions`): сообщённые клетки (`markNavigationCellsDirty`) перезаливают только затронутые кластеры; несообщённые мутаторы (аномалии, змея стен, Конвей) осознанно принимаются как «устаревшие до следующей плановой запечки» — единая система, независимая от геометрии и аномалий. Полный `bakeNavigationTree` только в двух точках: новый этаж и пост-самосбор. Детали — в [optimization.md](optimization.md) и [ai.md](ai.md).
3. **Запрет на снос кода (Anti-nuking)**: Никогда не переписывайте файл «с нуля» и не «упрощайте» его без прочтения полного содержимого. Делайте строго хирургические, локализованные правки.
4. **Запрет на гидравлический git reset**: Никогда не используйте `git reset --hard` или `git checkout .` без прямого указания пользователя, чтобы не уничтожить несохраненную работу.
5. **Каждый модуль предлагает выбор**: Каждый смысл-несущий игровой модуль должен предлагать игроку осознанный выбор (торговля, кража, починка, побег, подлог, скрытный обход).
6. **Чек-лист перед отправкой патча**:
   - Что изменилось и почему?
   - Где виден новый геймплей или какой путь отладки до него доходит?
   - Какой этаж, маршрут, зона или система его проверяет?
   - Как он реагирует на Самосбор?
   - Обновлены ли документы только для shipped-фактов?
   - Какие проверки прошлти (`npm run check:readonly` / `npm run check`)?
