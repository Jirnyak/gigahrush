# Security Policy for Jirnyak/gigahrush

## 1. Domain-Specific Threat Model
For 2.5D DDA Raycaster, Samosbor cellular automata, stash registry, dosimeter physics, our threat model includes:
1. **State Corruption**: Malicious inputs altering the simulation state.
2. **Denial of Service**: Algorithmic complexity attacks (e.g., O(N^2) paths).
3. **Memory Disclosure**: Out-of-bounds reads leaking internal state.
4. **Precision Loss**: Malicious floating-point inputs causing NaNs.
5. **Logic Bugs**: Exploiting the math in 2.5D DDA Raycaster, Samosbor cellular automata, stash registry, dosimeter physics to bypass constraints.
6. **Side Channels**: Timing attacks in the computation loop.
7. **Dependency Hijacking**: Compromised third-party libraries.
8. **Supply Chain Attacks**: Compromised build environment.

## 2. Supported Versions
We only support the latest main/master branch for Jirnyak/gigahrush. 
If you are running an older version, please upgrade.

## 3. Vulnerability Reporting
Report all vulnerabilities to the syndicate securely. Do not create public issues for security flaws.

## 4. Response Timeline
We aim to acknowledge reports within 48 hours and provide a patch within 14 days.

## 5. Security Architecture
Our architecture enforces strict boundaries. Memory is pooled, and inputs are sanitized at the edge.

## 6. Hardening Guidelines
- Enable all compiler warnings.
- Run fuzzers continuously.
- Use static analysis tools.
